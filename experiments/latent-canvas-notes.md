# Latent canvas: заметки с брейншторма (2026-09-22)

Исследовательские заметки по итогам сессии: как развить `noregeo_synth` из
генератора трейсов в исследование «модель сама обновляет своё внутреннее
визуальное состояние». Это **не** план эксперимента (нет кода) — карта идей,
литературы и предлагаемая программа. Когда что-то из этого станет
экспериментом, оно получит свой `.md` по стандартному формату.

## 1. Эволюция идеи за сессию

Три последовательные формулировки одной идеи:

1. **Латентный канвас** — модель обновляет свои хиддены на предыдущих шагах,
   связанных с картинкой, вместо перечитывания перерендеренного PNG.
2. **Текстовый MVP** — то же самое без мультимодальности: выделенные
   слоты-канвас, супервизируемые структурированным состоянием (список
   геометрических примитивов) через DETR-подобный лосс.
3. **RL-среда** — геометрическая задача как среда: действия = рисование
   (код/DSL), наблюдения обновляются, reward верифицируем. Пайплайн
   `noregeo_synth` уже является такой средой, используемой в режиме
   «сборщик отфильтрованных демонстраций».

Сходимость: DSL действий среды, словарь примитивов DETR-состояния и таргет
супервизии латентного канваса — одно и то же множество
(`point / segment / circle`). Среда, состояние и супервизия говорят на одном
языке.

## 2. Карта существующих работ: «внутренность» канваса

По степени того, насколько визуальное состояние внутри модели:

**(a) Внешний пиксельный канвас через код** — Visual Sketchpad,
Whiteboard-of-Thought, o3 «thinking with images». Ровно текущий
`noregeo_synth`: состояние в matplotlib, модель видит его через re-encode PNG.

**(b) Модель генерит картинки-мысли** —
[MVoT «Imagine while Reasoning in Space»](https://arxiv.org/abs/2501.07542)
(Chameleon-7B, интерливинг текст/картинка, token discrepancy loss). Дорого,
image generation мешает ризонингу.

**(c) Латентные визуальные токены (аппенд)** — ближайшее семейство:

- [Mirage «Machine Mental Imagery»](https://arxiv.org/abs/2506.17218)
  (CVPR 2026, [код](https://github.com/UMass-Embodied-AGI/Mirage)) — модель
  вставляет свои хиддены в последовательность как латентные визуальные
  токены. Обучение: (1) дистилляция латентов на эмбеддинги ground-truth
  картинок → (2) text-only supervision → (3) RL. **Стадия 1 требует ровно
  того, что наш пайплайн производит: GT-картинку состояния на каждый шаг.**
- [Latent Sketchpad](https://arxiv.org/abs/2510.24514) — Context-Aware Vision
  Head пишет визуальные латенты авторегрессивно, латенты прошлых картинок =
  долгосрочная визуальная память, Sketch Decoder рендерит их в картинки для
  интерпретации. Работает поверх Gemma3 / Qwen2.5-VL.
- Рядом: [Latent Visual Reasoning](https://arxiv.org/abs/2509.24251),
  Sketch-in-Latents (arXiv:2512.16584), IVT-LR «Reasoning in the Dark»
  (arXiv:2510.12603).

**(d) Перезапись уже записанных латентов** — почти свободная ниша. В
каузальном трансформере прошлые KV заморожены; что есть вокруг:

- [Bottlenecked Transformers: Periodic KV Cache Consolidation](https://arxiv.org/abs/2505.16950)
  — переписывает KV-кэш в ходе ризонинга (stale-cache аппроксимация работает);
- диффузионные LM — нативно ревизят прошлые позиции, но смена парадигмы;
- Recurrent Memory Transformer — memory-токены, переписываемые между
  сегментами (текст);
- [Coconut](https://arxiv.org/abs/2412.06769), Think-at-Hard, TTT/Titans —
  смежные механики латентного ризонинга;
- [A Survey on Latent Reasoning (arXiv:2507.06203)](https://arxiv.org/html/2507.06203v2).

**Ниша:** «латентный визуальный канвас с перезаписью на месте» не занят;
сравнение «аппенд vs перезапись при одинаковой супервизии» — готовый research
question, которого в литературе нет.

## 3. Текстовый MVP: структурированное состояние + DETR-лосс

Текстовая версия снимает vision tower и превращает проект в чистый вопрос:
Othello-GPT показал, что состояние мира *само* возникает в хидденах
([Li et al., ICLR 2023](https://arxiv.org/abs/2210.13382),
[линейные пробы Нанды](https://www.neelnanda.io/mechanistic-interpretability/othello));
работы по entity tracking показывают, что в natural language модели часто
*не* ведут состояние инкрементально, а лениво агрегируют на последнем токене
([Kim & Schuster](https://arxiv.org/abs/2305.02363),
[(How) Do LMs Track State?](https://arxiv.org/html/2503.02854v1),
[arXiv:2605.30233](https://arxiv.org/abs/2605.30233)). Вопрос: что даёт
явное состояние — выделенные слоты, плотная супервизия, перезапись.

### Ground truth уже в трейсах

- **Интроспекция артистов matplotlib** после каждого шага в `_runner.py`:
  `ax.lines` / `ax.patches` / `ax.collections` / `ax.texts`. `Line2D` с 2
  вершинами → отрезок; с многими → фит окружности (алгебраический, порог
  невязки) либо полилиния; `Circle`-патч → окружность; scatter (`mark`) →
  точка; `annotate` → имя. Полигоны канонизируются в отрезки. Run-директории
  реиграбельны (`preamble.py` + код в `record.json`), LLM не нужен.
- **`state`-словарь** преамбулы — бонусный именованный канал вычисленных
  величин.
- `verify.py` гарантирует `ink_loss = 0` → **состояние монотонно растёт**.

### Схема DETR-лосса

- M = 16–32 learned queries (конструкции ≤ ~15 примитивов).
- Выход слота: класс `{point, segment, circle, ∅}` + параметры фикс. длины 6
  (point: x,y; segment: x1..y2; circle: cx,cy,r), координаты нормированы в
  **фиксированный глобальный бокс** задачи (снимает проблему `expand_view`).
  Опционально — голова идентичности (имя точки) для probing/binding.
- Венгерский матчинг: цена `λ_cls·(−p_class) + λ_L1·L1(params)` по валидным
  размерностям; CE с down-weight ∅ (eos_coef ≈ 0.1), L1 на сматченных.
- **Персистентность слотов** (MOTR/TrackFormer track queries,
  [arXiv:2105.03247](https://arxiv.org/abs/2105.03247)): слот, сматченный с
  примитивом, остаётся привязан к нему; матчинг только «свободные слоты ×
  новые примитивы шага». Без этого identity churn шумит градиентами; с этим
  слоты = object files и update естественно инкрементален.
- База: [DETR, Carion et al. 2020](https://arxiv.org/abs/2005.12872).

### Лестница экспериментов

- **MVP-0, probe** (замороженная LM, обучается только голова): на токене
  конца каждого шага DETR-ридаут (M queries, 2–4 слоя кросс-аттеншена на
  хиддены префикса). Вопрос: декодируемо ли состояние, с какого слоя,
  деградирует ли с шагами. Othello-GPT-probing с set-structured пробой.
  Один GPU, дни.
- **MVP-1, aux loss**: LoRA-SFT на трейсах + DETR-лосс на границах шагов
  против того же SFT без него; метрика — solve rate на held-out
  (`--no-reveal-answer`).
- **MVP-2, канвас с обратной связью (аппенд)**: слоты после шага k
  проецируются во входное пространство и вставляются блоком
  `[CANVAS] e₁…e_M [/CANVAS]` перед шагом k+1. Coconut/Mirage-механика с
  DETR-супервизией.
- **MVP-3, перезапись на месте**: канвас-блок на фиксированных позициях после
  условия; после каждого шага его KV пересчитываются, KV старых шагов честно
  протухают (аппроксимация Bottlenecked Transformers). **MVP-2 vs MVP-3 —
  главный вопрос.**
- **Killer demo — интервенция в канвас**: подвинуть точку в слотах и
  проверить, следует ли за ней рассуждение (аналог каузальных интервенций на
  Othello-GPT).

### Риски

- **Ридаут-парсер**: проза шагов называет координаты — ридаут может парсить
  текст, а не вести геометрию. Диагностика: маскирование чисел в тексте на
  eval. Радикально: **предиктивная супервизия** (канвас предсказывает
  состояние *после следующего* шага до генерации его текста) — план в
  латентном пространстве, парсингом не подделывается.
- **Мало данных**: пилот 27/27 за 12 мин → ~2–3k трейсов за ~20 ч эндпоинта;
  для LoRA + голов достаточно на MVP.
- Стандартные DETR-боли (нестабильный матчинг в начале, коллапс слотов) —
  при M=16 мягкие.

### Про представление данных (если возвращаться к картинкам)

Текущие PNG — артефакты проверки, не таргеты дистилляции: `expand_view`
ломает пространственную согласованность между шагами (нужен второй рендер в
фиксированном глобальном view box), сетка/оси/тики/легенда — мусор в
эмбеддинг-таргете (нужен «чистый» рендер). Картинки возвращаются позже как
*второй* таргет тех же слотов, не замена примитивов.

## 4. RL-среда: геометрия как environment

Маппинг существующего пайплайна на env-интерфейс:

- `reset()` = преамбула (`canvas.py`);
- действие = фрагмент кода шага; `guard.py` + subprocess = динамика;
- наблюдение = перерендеренный канвас (PNG и/или примитивы);
- reward = `verify.py`: терминальный (golden match, drawn-answer) + shaping
  (шаг рисует, ink_loss=0) + анти-хак (`literal_leak` — **уже пойманный
  reward hacking с построенной защитой**);
- repair rounds = multi-turn feedback;
- текущий пайплайн = rejection sampling / STaR-подобный behavior cloning.

### Подходы по четырём линиям

**Multi-turn agentic RL (инфраструктура):**
[RAGEN/StarPO](https://arxiv.org/abs/2504.20073) — trajectory-level RL;
failure mode «Echo Trap» (коллапс без стабилизации), без reasoning-aware
реворда рассуждение само не возникает.
[VAGEN](https://github.com/RAGEN-AI/VAGEN) — сиблинг для VLM,
**World-Modeling RL**: явная супервизия state-estimation /
transition-prediction во время роллаутов — мостик к латентному канвасу.
Стек: [verifiers](https://github.com/willccbb/verifiers),
[SkyRL-Agent](https://arxiv.org/abs/2511.16108),
[OpenEnv](https://huggingface.co/blog/openenv-agentic-rl),
[обзор RL-библиотек (Anyscale)](https://www.anyscale.com/blog/open-source-rl-libraries-for-llms).
Рецепт: SFT cold-start → multi-turn GRPO с verifiable reward.

**Thinking with images через RL (действия над картинкой):**
[DeepEyes](https://arxiv.org/abs/2505.14362) — zoom-in как действие,
возникает чистым RL без SFT;
Pixel Reasoner (NeurIPS 2025) — curiosity-driven;
[VTool-R1](https://arxiv.org/abs/2505.19255) — внешний Python модифицирует
картинку, результат в контекст;
**ViLaSR** («Interwoven Thinking and Visual Drawing», 2025) — модель рисует
на изображении, ближе всего к нашему рисованию;
[Visual Planning / VPRL](https://huggingface.co/papers/2505.11409)
(ICLR 2026) — планирование чисто картинками; урок: SFT коллапсирует в
низкоэнтропийное повторение, RL сохраняет разнообразие — аргумент за
RL-этап после BC.
Survey: [Thinking with Images (arXiv:2506.23918)](https://arxiv.org/abs/2506.23918).

**Геометрические среды:**
Euclidea как RL/imitation-среда —
[Learning to solve geometric construction problems from images](https://arxiv.org/abs/2106.14195),
[EuclidNet](https://arxiv.org/abs/2301.13007): инструменты с
аргументами-кликами, наблюдение — картинка, аналитическое состояние скрыто.
AlphaGeometry /
[AlphaGeometry2](https://deepmind.google/blog/ai-solves-imo-problems-at-silver-medal-level/):
вспомогательные построения = действия, символьный движок = динамика.
[InternGeometry (arXiv:2512.10534)](https://arxiv.org/abs/2512.10534)
(ICLR 2026) — Think → Action (DSL) → Feedback с символьным верификатором,
44/50 IMO-геометрии на 32B. **Ниша: у всех feedback символьный, у нас —
визуальный; «читает ли модель канвас» никто не проверяет, у нас есть
методология `eval_blind`.**

**Робототехника / world models (концепты):**
трейсы = teleoperation demos, SFT = behavior cloning; болезнь BC —
distribution shift на своих роллаутах → DAgger / RL-дообучение (путь
VLA-моделей OpenVLA/π0). **Dreamer/RSSM**: рекуррентное латентное состояние,
обновляемое действием, + observation-лосс — это и есть «латентный канвас с
перезаписью» под каноничным именем **world model / belief state в POMDP**.

## 5. Объединённая программа

1. **Среда**: gym-обёртка вокруг `execute.py`/`verify.py` (reset/step/obs/
   reward уже написаны); возможно сузить действия с произвольного matplotlib
   до DSL (`draw_point/draw_segment/draw_circle` + compute) — меньше
   поверхность reward hacking, дешевле парсинг.
2. **BC**: SFT на accepted-трейсах (данные уже генерятся).
3. **RL**: multi-turn GRPO (verifiers / VAGEN), reward из `verify.py`;
   арматура эксперимента — режимы наблюдений: пиксели / примитивы / без
   (open-loop). **Центральный вопрос: помогает ли модели видеть результат
   собственных действий (closed-loop vs open-loop).**
4. **World model**: латентный канвас с DETR-супервизией как belief state
   политики; сравнение аппенд (MVP-2) vs перезапись (MVP-3).

Пункты 1–3 — работающая система и публикуемый результат сами по себе;
пункт 4 — архитектурная надстройка, которую среда позволяет честно аблировать.
Мультимодальная версия (Mirage-style дистилляция на эмбеддинги чистого
рендера) добавляется заменой таргета супервизии, без смены архитектуры.
